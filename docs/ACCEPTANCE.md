# Acceptance gates

1. Public-source review: no credentials, identity-bearing records or original market data. Preserve old repository and all rejected-model evidence. No automatic historical strategy imports.
2. Linux CI: shared core checks and actual `.algo` compilation. Inspect artifact contents and dependency closure. Current synthetic checks prove only specified protective behavior and round-trip accounting cases.
3. Read-only integration: OWNER installs existing secrets in protected environments after collector review. Prove OAuth scope/account binding, pagination, authentic decoder outputs and encrypted custody. Publish only sanitized provenance. No orders or Cloud activation.
4. C# economic replay: authentic data, continuous EUR 200 ledger, executable costs/FX/financing/margin, shared decision core, reproducible hashes and parity. Minimum 12 months total evaluated with predeclared chronological development/selection/confirmation allocation.
5. Qualification: independently evaluated NET edge and uncertainty, predeclared eligible weeks, HARD21 complete positions (partial exits are not additional trades), drawdown stress, correlated exposure, no forced trades. No result presumed.
6. Restart acceptance: partial fills, duplicate/out-of-order events, foreign positions, missing data, cashflows, ambiguous request outcomes, missing peak certificate and adaptation replay. Protective mode alone is not evidence of full autonomous recovery.
7. Android/Cloud acceptance only after explicit OWNER authorization for the relevant activation: import compiled `.algo` on Android, Linux Cloud load, start/stop controls, restart, reconciliation and owner emergency stop. No Desktop requirement. No LIVE/DEMO order is authorized by this document.

Only the final economic and operational evidence supports a later OWNER activation decision. The current build is not a trading product and must not be activated.
